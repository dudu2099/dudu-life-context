# 收尾：全部转正、撤回、检查、导出、原话

这几件事都是一两条命令，核心是先看再动：转正和撤回都会改一批文件，改之前把将要发生的事告诉用户一句。

下面命令里的 `<本技能目录>` 是这个 skill 所在的文件夹；调用者给了测试根目录，每条命令都加 `--root "<测试根目录>"`，没给就不加。

## 全部转正

用户看过、删改完，说「全部转正」「都转正」「没问题了」。

```bash
python3 "<本技能目录>/scripts/confirm.py" --dry-run
python3 "<本技能目录>/scripts/confirm.py"
python3 "<本技能目录>/scripts/commit.py" -m "转正：N 条待确认 → 已确认"
```

- 先 dry-run 看条数，跟他说一句「转 N 条」就直接真跑，不用再等他点头：「全部转正」就是他的点头。
- 他只说转某一章（「表达那章可以了」），加 `--file 01-我是谁/5-表达.md`，只转那个文件。
- 报告里列过的矛盾他还没定，转正前提醒一句：那两条会一起转正，要不要先删掉一条。他说不管，就照转。
- 转完跑一次 `check_format.py`，告诉他还剩几条待确认（应该是 0，除非只转了部分文件）。

## 撤回这次填充

用户说「撤回这次填充」「这批不要了」「恢复到填充前」。

```bash
python3 "<本技能目录>/scripts/undo.py" --dry-run
python3 "<本技能目录>/scripts/undo.py"
```

- dry-run 写明恢复到哪一份备份、那份是什么时间，分开列出「会删掉」「会写回旧版」「会补回来」。**把「会删掉」和「会写回旧版」两张清单都原样告诉他**：「会删掉」是备份之后才出现的所有文件，包括他自己后来新建的；「会写回旧版」是备份之后被改过的文件，现在的版本会被盖掉，包括他自己后来的改动。标了【你的原话区】的（`03-流水/`、`04-项目/*/记录.md`）是他自己记的原话，单独点出来问一句。他说可以，再真跑。
- 默认恢复到最新一份「填充前」备份（先后按备份清单里记的 UTC 时间排）。有一次填充正在进行、它开工前的那份备份却被删了，undo 会拒绝：没有能恢复到这次填充前的备份了，照实告诉他，不要自己挑一份更早的。上一次撤回已经恢复到某份、这次默认选出来的不比它新，undo 也会拒绝并说明：这是在防止连续撤回悄悄越过上一次。告诉他会退到哪一份、什么时间，他同意了再用 `--backup <名字>` 指定。用 `--backup <撤回前那份>` 反悔过之后，这条保护重置。
- undo 会先把现在的样子另存一份「撤回前」备份，所以撤错了还能换回来：`undo.py --list` 看所有备份，`undo.py --backup <那份的名字>` 恢复到那份。
- 撤回之后照实告诉他三件事：撤回前的样子存在了哪个备份里，**里面仍然有这批内容**；要彻底删掉，用 `undo.py --delete-backup <那份的名字> --yes`（不带 `--yes` 只打印会删什么）；用了 git 的话，git 历史里也还有，要他自己处理。
- 备份只增不减，每次填充都整份复制一次。他嫌占地方，`--list` 看有哪些，他点名哪份，先不带 `--yes` 跑一遍给他看，再带 `--yes` 删。
- 他只想撤掉某一章，不是整批：不用 undo，直接用 Edit 删掉那几条，或者从备份文件夹里把那一个文件复制回来。
- 文件夹自己是 git 仓库的，undo 会自己提交一次（只提交上下文文件夹自己的文件）；不是的、或它在别人更大的仓库里的，不提交，备份就是全部的历史。

## 检查上下文

用户说「检查上下文」「看看上下文有没有乱」。

```bash
python3 "<本技能目录>/scripts/check_format.py"
```

把结果分两块告诉他（「疑似凭据」一组只给位置不给内容，你也不复述那一行）：格式问题（每条带文件和行号，说打算怎么改，他同意再改）、还有多少条待确认。半年没更新的条目逐条问他还成立吗：成立就把年月改成现在，变了就按规范写成「现在……（原来……）」，不成立就删。私密条目脚本只给位置，你也不去打开看。

重复、意思重叠的条目脚本查不出来。他要你顺便查，就按文件读（不读 `99-附录/` 和私密条目），找出 AI 读了会做出一样的事的几条，提议合并，他点头再改。

## 导出上下文

用户说「导出上下文」「导一段给别的 AI」。

1. 卷首「一页纸的我」总会带上。别的章节要他点名；他没说，就问一句拿去干什么，从卷首章节状态表里「有内容」的章节挑三四个建议给他。不默认全导。
2. 跑：

   ```bash
   python3 "<本技能目录>/scripts/export.py" --chapter 01-我是谁/5-表达.md --chapter 02-素材/观点库.md
   ```

   导出文本在标准输出，统计和提醒在标准错误，两样都看。私密的永远不导；待确认的默认不导（他要连待确认一起带走，加 `--include-pending`）。
3. 超了 1000 字（退出码 2），把统计里各部分的字数给他看，问他删哪块：去掉整章就不带那个 `--chapter`，去掉某几条用 `--skip "<那条里独有的一段字>"`。不要自己挑着删。
4. 把导出文本完整放在一个代码块里给他。统计里提到「仅助理」的，附一句：这段贴给你自己用的 AI 没问题，别贴到公开场合。他要存文件，加 `--out "<上下文文件夹外的路径>"`。

## 原话

用户说「列出原话」「我贴的话存在哪」「删掉某份原话」。

```bash
python3 "<本技能目录>/scripts/save_raw.py" --list
python3 "<本技能目录>/scripts/save_raw.py" --delete "<短名或文件名>"
python3 "<本技能目录>/scripts/save_raw.py" --delete "<短名或文件名>" --yes
```

- `--list` 列出 `99-附录/_原始材料/` 里每一份的出处名和文件名，照实告诉他。
- 删之前先不带 `--yes` 跑一遍，把会删哪份、用它写的条目以后核不回出处，告诉他；他点头再带 `--yes`。
- 删完照实说：填充前备份里还有副本（要彻底删，见上面「撤回这次填充」里删备份的做法，他点名哪份删哪份）；用了 git 的，git 历史里也有，要他自己处理。
